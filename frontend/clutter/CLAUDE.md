# frontend/clutter

Next.js 16 (App Router), React 19, React Flow (`@xyflow/react`), TanStack Query, Zustand, Tailwind 4, shadcn-style components in `src/components/ui`. Code rules: `engineering-conventions` § Frontend.

Traps:

- **npm is the package manager.** The Dockerfile runs `npm ci` against `package-lock.json`. Install with `npm ci`.
- **Next 16 and React 19 APIs differ from what you remember.** Request interception lives in `src/proxy.ts` (the Next 16 name for middleware). Check current docs before using a Next or React API.
- **The canvas is AWS-shaped.** `Palette.tsx`, `nodes/AwsServiceNode.tsx` and `nodes/ConfigPanel.tsx` hard-code AWS services, icons and option lists. These are A's screens and stay AWS-only (ADR-006). B's editor and Connections page are new and read each connector's manifest from B's API, never these lists. An A resource change follows `add-cloud-resource`.
- **Option lists here must match the backend.** The Lambda runtime list copies `generic.LambdaRuntimes` in the backend, which refuses any other runtime. The AWS connection form's Region is the B connection's region only: the account link still opens AWS in `ca-central-1` (`DEFAULT_AWS_REGION` in `organization/api.ts`), and `runTerraform` never sends a region, so every A deploy runs in the backend's `generic.DefaultRegion` (Clutter's own region, from the Lambda's `AWS_REGION`). Ansible job statuses (`AnsibleJobStatus` in `runs/types.ts`) copy the backend's `AllowedJobStatuses`; polling stops on `COMPLETED` or `FAILED`.
- **A diagram's editor is chosen by its saved document.** `engine: "blocks"` opens B's editor, anything else A's. `normalizeDiagram` in `diagram/api.ts` must keep `engine`, or every building-block diagram opens in A's editor. A's create route ignores `data`, so `useCreateDiagram` saves the marker with a second `PUT /diagram`.
- **B's screens never read A's AWS lists.** Blocks, fields, defaults, allowed values, edges and settings come from B's catalog (`catalog/forms.ts`); credential forms from each connector's credential spec. B's errors come in one envelope, read once in `src/lib/adapterApi.ts`.
- **A's API is called through one helper, and its error message stays the raw body.** `apiFetch` in `user/session.ts` throws an `ApiError` with the status; A's editor parses `error.message` as JSON for the diagram's problems, so do not rewrite it. Pages show their own plain sentence, never `String(err)`. An expired token (B's 401, A's gateway 403 "not authorized") is caught once, in `src/app/providers.tsx`; `logs`, `runs`, `resources` and `codeUpload` still keep their own fetch copies.
- **There is no `test` script.** The Vitest files sit beside the code in `lib/features/` (for example `diagram/types.test.ts`), and one, the editor's leave guard, in `src/app/` with `// @vitest-environment jsdom` as its first line, since the default environment has no DOM; run them with `npx vitest run`; CI runs them too (`.github/workflows/checks.yml`). Vitest runs without the `@/` alias, so a module a test imports reaches its siblings by relative path. `lint` is the only script check. To see a change against real data, run the app locally (`frontend/clutter/README.md` § Run it).
- **The browser test reads labels.** `tests/e2e/workflow.e2e.ts` finds elements by `data-testid` and by accessible names ("Destroy for good", "Remove from diagram", "Up to date"); renaming one breaks it, so change the test in the same change.
- **Style with tokens and `surface-card`, never raw palette classes or `dark:`.** Colours come from the Radix-based tokens in `globals.css`, and a block kind's or a team's colour from `KIND_TINT` (`catalog/display.ts`) and `lib/tint.ts`, never a class like `bg-blue-500`; `dark:` does not match inside a `.light` scope (sign-in, onboarding, the landing page), so a screen styled with it breaks there.
- **Never name a custom utility `bg-*` if it goes through `cn()`.** tailwind-merge takes it for a background colour and drops it, or the real fill, from the class list (that is why the grain utility is `grain`).
- **The logo's colours have one owner, `components/brand/logoColours.ts`.** `public/logos/clutter-mark.svg` and `src/app/icon.svg` draw the same colours by hand, so change both files with it.
- **The dev server can keep serving stale CSS after a `globals.css` change** (a Tailwind `@utility` edit, or a production build while `npm run dev` runs). If a change does not show, stop `npm run dev`, delete `frontend/clutter/.next/dev` (generated), and start it again.
- **Dark is the default theme, and some scopes are fixed.** Sign-in and onboarding are always light (`(auth)/layout.tsx`) and the sidebar always dark; look at a changed screen in light and dark.
- **A's editor stays unedited inside `ThemeScope theme="a-editor"`.** `EditorSwitch` wraps it; change the wrapper or the `.a-editor` tokens, never A's editor files (ADR-006). A's buttons are the shared `Button`, so a change to it reaches A's editor too (its Terraform preview's buttons already take the shared 32 px height and outline style); scope such a change out of `.a-editor`.
- **Browser-only memory goes in the preferences store.** `lib/features/preferences/uiStore.ts` owns the onboarding answers and per-team UI memory under one key; add a field there, never a new `localStorage` key.
- **There is one connection flow.** Every "connect a cloud" opens `ConnectCloudSheet` (the empty Connections page shows `ConnectCloudFlow` inline); never build a second form or link to the old AWS account page, which only redirects.
- **Cloud logos render only through `CloudLogo`.** Its `SHOW_OFFICIAL_CLOUD_LOGOS` switches every place back to neutral tiles (ADR-022, revised); a logo drawn any other way escapes that switch.

Server data lives in `src/lib/features/<feature>/` (`api.ts`, `types.ts`, `keys.ts`, `hooks.ts`, optional `uiStore.ts`). Follow that shape for a new feature.
