# backend/adapter

- **A child process with a nil `exec.Cmd.Env` inherits B's whole environment**, which holds the database string, the credential key and the JWT secret. Start run processes only through `internal/runtask`, which always passes the run's own environment, built from nothing.
- **Only `cmd/api/main.go` names a connector** (its `available` map). Anything else that branches on a connector id is a defect; ask the registry and call the interface.
- **Every store query a request reaches that takes a diagram, connection, deployment or run id also takes the organization id and filters on it.** Deployments and runs are scoped through both their connection and their diagram's project. A new such query without that filter is a cross-tenant read. One exception, on purpose: the code-object checks behind code replace, code remove and the hourly sweep (`UnreferencedCode`, `DeleteUnreferencedCode`) look across every organization's `function_code` rows, because an object any row names must stay; they return only whether a key is in use, never a row. Only the job runner's own writes (`RunStarted`, `RunFinished`, `RunParts`, `SetDeploymentStatus`) and `FailInterrupted` take no organization: they act on runs B queued after a scoped request, and no request reaches them.
- **`adapter-tables.sql` runs at every start-up.** Every statement in it must stay idempotent (`IF NOT EXISTS`, guarded `DO $$` blocks, `CREATE OR REPLACE`).
- **A credential value never reaches a log, a response or a `Problem`.** `connectors.Secrets` prints as `[redacted]`, and the job runner removes credential values from run logs, but only for values it was handed. A connector that derives a new secret (a session token) must not print it.
