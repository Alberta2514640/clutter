# PatriCloud product identification

Research date: 26 October 2026. Pages below were fetched that day unless a source date is quoted. Exact strings PatriCloud, Patricloud, patriicloud, and Pattricloud did not match a public product. The closest live product is **Patrii Cloud** at [patrii.cloud](https://patrii.cloud/) (double i).

## Which entity is the real one, and which spellings are dead ends?

### Takeaway
Patrii Cloud (patrii.cloud), sold by Patrii Québec inc. on technology owned by Patrii Cloud inc., is the only current public cloud product that the queried spellings plausibly mean. Exact names PatriCloud / Patricloud / patriicloud / Pattricloud have no matching site. Patriot Cloud, Particle Cloud, Patr, Patrimóvel Cloud, and an Indian training-shop listing are different entities. The local Clutter report does not name Patrii or any of these spellings.

### Cited Findings
- Official product home, in public beta since 18 June 2026, brands itself “Patrii Cloud,” “Canada's truly sovereign cloud infrastructure,” Montreal, from $5.25 CAD/month plus tax — [patrii.cloud](https://patrii.cloud/).
- About page: founded 11 July 2025 in Greater Montreal; mission is a sovereign, open, transparent cloud for local businesses; founders’ prior company named as KeepSec Technologies; only named person is Guillaume Harvey, “Co-Founder, CEO & CTO,” with prior work at Ormuco, Ubuntu/Canonical, KeepSec, and consulting for Bell Canada, Morgan Stanley, and Intact Insurance — [patrii.cloud/about](https://patrii.cloud/about).
- Terms, last updated 7 September 2026: services are “sold and provided in Quebec and elsewhere in Canada by Patrii Québec inc., on technology owned and operated by Patrii Cloud inc., running on servers located in Montreal, Quebec, Canada.” “Patrii” in the terms means both companies. IP stays with Patrii Cloud inc. Contact: legal@patrii.ca, Patrii Québec inc., Legal Department, 927 Dalhousie, St-Jerome, QC J5L 0A7, Canada. Governing law: Quebec and federal Canadian law — [patrii.cloud/legal/terms](https://patrii.cloud/legal/terms).
- Privacy policy, last updated 24 July 2025 (older than the terms and older than the June 2026 beta banner): same two company names; privacy contact privacy@patrii.ca; DPO dpo@patrii.ca; same St-Jerome address — [patrii.cloud/legal/privacy](https://patrii.cloud/legal/privacy).
- Blog byline on 2 March 2026: “Patrii Quebec inc., Guillaume Harvey” — [ACME certificates post](https://patrii.cloud/blog/real-features-real-screenshots-acme-certificates-with-secret-as-a-service-25).
- Data processing agreement, last updated 24 July 2025, instead names the processor as “Patrii Inc.” while the terms and privacy policy name Patrii Québec inc. and Patrii Cloud inc. Sub-processors are said to be listed at patrii.ca/legal/subprocessors; that URL was not fetched — [patrii.cloud/legal/dpa](https://patrii.cloud/legal/dpa).
- GitHub account `PatriiCloud` (account type User, not an Organization), company field “Patrii Cloud,” location Greater Montreal, blog https://patrii.cloud, joined 2025-07-25. Two public repos — [github.com/PatriiCloud](https://github.com/PatriiCloud).
- `PatriiCloud/terraform` (“Patrii Cloud Terraform Provider. A Canadian Sovereign Cloud Platform”) was created and last pushed 2025-12-14, size 0, language null, 0 stars. It is an empty repository, not a published provider — [GitHub API](https://api.github.com/repos/PatriiCloud/terraform).
- `PatriiCloud/magnum-cluster-api` is a fork of [vexxhost/magnum-cluster-api](https://github.com/vexxhost/magnum-cluster-api) (“Cluster API driver for OpenStack Magnum”), Apache-2.0, language Rust, created 2025-10-28, last push 2026-08-23. It is upstream OpenStack Magnum code, not a Patrii customer API — [GitHub API](https://api.github.com/repos/PatriiCloud/magnum-cluster-api).
- Developer-docs host `https://docs.patrii.cloud` returned HTTP 500 on 26 October 2026. The marketing docs page says “Documentation Coming Soon” — [patrii.cloud/documentation](https://patrii.cloud/documentation).
- Fetch of `https://patri.cloud/` (single i, no second i) returned HTTP 500. No public site at that exact host was readable. Search for that domain surfaced patrii.cloud and patr.cloud instead.
- **Patr** (patr.cloud) is a different product: an open-source, self-hosted app platform in closed beta, run by an unnamed individual maintainer (“I”), aimed at deploying containers or repos onto a VM, Kubernetes cluster, or bare metal the user already owns. Docs exist, including domain setup — [patr.cloud](https://patr.cloud/), [docs.patr.cloud/features/domains](https://docs.patr.cloud/features/domains).

REST API host `https://api.particle.io`, OAuth2 access tokens, device resources — [Cloud API reference](https://docs.particle.io/reference/cloud-apis/api/), [introduction](https://docs.particle.io/getting-started/cloud/introduction/).
- **The Patriot Cloud** (“Freedom's Cloud”) is a separate US managed-hosting / MSP brand. Search snippets describe hosted storage, SaaS, email/video/web hosting, and VMware-certified engineers, with private, public, and hybrid options. Indexed URLs are on `thepatriotcloud.flywheelsites.com`, which was not fetched in full — [hosted solutions](https://thepatriotcloud.flywheelsites.com/about-data/hosted-solutions/), [infrastructure](https://thepatriotcloud.flywheelsites.com/infrastructure/).
- **Patrimóvel Cloud** is a Brazilian real-estate lead and listings app by Lopes, Android package `br.com.lopes.patricloud`, Play listing updated 7 August 2024. Unrelated to infrastructure — [Google Play](https://play.google.com/store/apps/details?hl=pt_BR&id=br.com.lopes.patricloud).
- A third-party Indian GST directory lists a place of business as “Patri Cloud Computing Training Institute,” 85/413-4 Palakonda Road, Kadapa, Andhra Pradesh 516002. That is a directory entry for a training shop, not a cloud platform, and it is not a government page — [indiacos.com GST record](https://indiacos.com/gst/37AFBPV9613A1ZH).
- A 2010 Devoxx slide deck on Google App Engine / Gaelyk contains OCR that looks like “Patri Cloud.” The slide is a speaker-thanks slide (Guillaume Chanezon / Groovy), not a product — [SlideShare](https://www.slideshare.net/slideshow/google-app-engine-java-groovy-baby/2540031).
- Local Clutter sources do not name Patrii or PatriCloud. `README.md` is the capstone title page: project Clutter (500-MM-3-Clutter), University of Calgary team, academic advisor Lorenzo De Carli, and **Alberta 2514640 Inc / Devin Atkin** (devin.atkin@alberta2514640.ca), dated 2026-06-08. PDF text extraction of `500-MM-3-Clutter-Final-Report.pdf` matches “patri” nowhere. The sponsor is Alberta 2514640 Inc.; Clutter “was built” / “Developed for Alberta 2514640 Inc.” as a drag-and-drop web GUI that generates Terraform/Ansible for AWS. Copyright line: “Copyright (c) 2026 Alberta 2514640 Inc.” Frontend was hosted on a sponsor-provided VM. No partner adapter, marketplace, or Patrii integration is described.

### Inferences
- “PatriCloud,” “Patri Cloud,” “Patricloud,” and “patriicloud” are spellings of Patrii Cloud (the French *patrie* plus “cloud,” with the doubled i in the brand and domain). That is an inference from the name, the about-page explanation of “patrie,” and the absence of any other current product using those exact strings. The about page itself says the name stands for homeland/sovereignty only on the LinkedIn-style snippet in search, not on the fetched about page. The fetched about page does not define the word “Patrii.” Treat the *patrie* etymology as unconfirmed on the official about page.
- Clutter, as documented in this repo, is an AWS IaC diagram tool for Alberta 2514640 Inc. Nothing in the report makes Patrii Cloud its partner.

### Gaps
- No Quebec enterprise-registry (REQ) extract was opened, so incorporation numbers, directors beyond Guillaume Harvey, and share structure are not confirmed. The DPA’s “Patrii Inc.” is inconsistent with the terms and was not resolved.
- LinkedIn company page `linkedin.com/company/patrii` appeared in search (homepage patrii.cloud, founded 2025) but was not fetched. Employee counts and the “info@patrii.ca” address from that search snippet are not used as facts.
- `https://patri.cloud/` returned HTTP 500, so a parked or broken site at that host is possible and was not ruled in or out.
- The Patriot Cloud Flywheel pages were not fetched in full, so whether that MSP is still operating is unknown.
- Community-page counters (“100+ community members,” “50+ active contributors,” “10+ community projects”) sit on a page that also says GitHub is “coming soon” and lists no events — [patrii.cloud/community](https://patrii.cloud/community). Those counts were not independently verified and conflict with the public GitHub account that already exists. Do not treat them as audited figures.

## What does the product do, for whom, and what are its core concepts?

### Takeaway
Patrii Cloud is a young Canadian public-cloud beta for startups, agencies, and enterprises that want compute, network, storage, databases, Kubernetes, DNS, and certificates hosted in Canada. Public docs name accounts and, in one blog post, projects. They do not publish a tenant, organization, or workflow resource model.

### Cited Findings
- Audience on the home page: startups and developers (MVP hosting, free credits for qualified startups), enterprise workloads (99.9% SLA, “private cloud options,” dedicated account management), and digital agencies (multiple client sites, bulk pricing) — [patrii.cloud](https://patrii.cloud/).
- Catalog on the services page, presented as current technical specifications: shared VPS (Ubuntu, Debian, Fedora, AlmaLinux, Rocky, CentOS; custom images; SSH root; public IPv4; unmetered bandwidth; 99.9% uptime SLA); block storage (16K IOPS, 250 MB/s, triple replication, AES-256 at rest, snapshots); S3-compatible object storage (99.99% durability, multi-region replication, lifecycle policies); networking (1 Gbps public, VXLAN, stateful security groups); floating IPs; snapshots; custom images (qcow2, raw, vmdk, up to 100 GB, cloud-init); managed databases (PostgreSQL, MySQL, Valkey, FerretDB); load balancers (Basic, Standard, HA; L7; TLS termination); authoritative DNS with import from Cloudflare, GoDaddy, and Route 53; domain registration; automatic TLS certificates; PaaS described as “Managed Coolify on your own instance”; NFS/CIFS shares; managed Kubernetes. Separate product line: “Lynx ERP/CRM/GRC,” “hosted and maintained by Patrii,” “learn more at lynx.patrii.ca” — [patrii.cloud/services](https://patrii.cloud/services). lynx.patrii.ca was not fetched.
- Explicitly marked “coming” on that same services page: cross-region snapshot copy, snapshot scheduling, image sharing, and a marketplace.
- Stack named on the services page: orchestration “OpenStack Epoxy”; storage “Ceph distributed storage (3x replication)”; networking “Open vSwitch with VXLAN”; monitoring “Zabbix + Prometheus + Grafana”; virtualization “KVM”; example hardware Intel Xeon, SSD with NVMe cache, 1 Gbps public and 10 Gbps private. Home page also names FreeIPA alongside OpenStack and Ceph — [patrii.cloud](https://patrii.cloud/), [services](https://patrii.cloud/services).
- Pricing page (French URL fetched via search snippet, English pricing URL indexed): prices in CAD before tax; lowest cited instance $5.25 CAD/month; beta offer “7-day free trial with $10 CAD credit. No credit card required”; bandwidth “unmetered”; live resize claimed. Instance families named: Balanced, CPU Optimized, General Purpose, Memory Optimized — [patrii.cloud/fr/pricing](https://patrii.cloud/fr/pricing), [patrii.cloud/pricing](https://patrii.cloud/pricing).
- Terms section 2 lists a broader set than the services catalog: virtual compute instances and containers, object and block storage, networking and security, “database and analytics platforms,” “AI/ML services and tools,” and “API access and integration services.” GPU as a Service is on the roadmap for Q1 2027, not in the current catalog. The terms list and the catalog disagree on AI/ML — [terms](https://patrii.cloud/legal/terms), [services roadmap](https://patrii.cloud/services).
- Billing model in the terms (7 September 2026): CAD; automatic renewal; cancel before the term ends; fees are for “the quota allocated to your account rather than metered by the hour”; deleting or shelving resources mid-term does not prorate or refund — [terms](https://patrii.cloud/legal/terms).
- Accounts: terms require an account and make the customer responsible for credentials; cancellation is “through your account dashboard” — [terms](https://patrii.cloud/legal/terms).
- Projects: the 2 March 2026 blog says the console lists “zones managed by your project through DNS as a Service,” and describes Secret Vault, Secret Containers, ACME certificates tied to those zones, and retrieval “through the API.” The post says screenshots are from an internal build and that this is “the upcoming Patrii Cloud release,” so it predates the 18 June 2026 public beta — [blog](https://patrii.cloud/blog/real-features-real-screenshots-acme-certificates-with-secret-as-a-service-25).
- Roadmap still labeled “Current / Q3 2026” on the services page as fetched 26 October 2026 (after Q3 ended): PaaS (Coolify), VPN Interconnect, Migration as a Service, Managed Databases, SSO. Q4 2026: Workflow as a Service, Log as a Service, WAF, disk tiers, start of ISO 27001 and SOC 2 Type II programs. Q1 2027: GPU as a Service, Identity as a Service, ISO 27001 complete. Q2 2027: SOC 2 Type II complete. Page says the roadmap can change. Several items in “Current” are also described above the roadmap as available services, so the page does not cleanly separate shipped from planned — [services](https://patrii.cloud/services).
- No public page fetched defines tenants, organizations, a resource hierarchy, or a workflow object. “Workflow as a Service” is a Q4 2026 roadmap item, not a documented concept.

### Inferences
- The console object that third parties would most likely scope to, based on the only concrete noun in a product post, is a **project** that owns DNS zones and secrets. Accounts exist in the contract. A tenant/org model is not documented and should not be assumed.
- “Private cloud options” on the home page, next to dedicated account management, most likely means a Patrii-operated dedicated environment for enterprise customers, not software the customer installs. The pages never say customers can run the Patrii control plane themselves.

### Gaps
- No public data model, console IA, or glossary for org / tenant / project / resource / workflow.
- Whether managed databases, Coolify PaaS, and Kubernetes listed on the services page were generally available on 26 October 2026, or still the Q3 roadmap, cannot be settled from these pages alone.
- Region list is not published. Sample JSON uses `montreal-1`, but that string appears only inside “coming soon” examples (see integration section) and is not confirmed as a live region id. Home page says “Montreal data centers” (plural) and “sub-5ms latency across major Canadian cities” without naming other sites.
- Lynx (lynx.patrii.ca) was not opened.

## What principles does its documentation state?

### Takeaway
Marketing states API-first design, open-source infrastructure (OpenStack, Ceph, FreeIPA), avoidance of vendor lock-in, and intent to support Terraform, Ansible, Kubernetes, OpenAPI 3.0, webhooks, and a future image marketplace. There is no published documentation set. Multi-cloud is not a stated principle. The customer REST API is explicitly “in development.”

### Cited Findings
- Home page: “Our API-first approach ensures your infrastructure can grow programmatically.” Open-source stack “OpenStack, Ceph, FreeIPA,” contrasted with VMware and OpenShift and the US CLOUD Act. “Built on OpenStack, avoiding vendor lock-in. Use familiar tools like Terraform, Ansible, and Kubernetes. Full API compatibility ensures your automation works seamlessly.” It does not say compatibility with which API — [patrii.cloud](https://patrii.cloud/).
- About page principles, as headings: innovation, security by design, customer first, transparency; “avoid any vendor lock-in”; “the cloud must be free, lean, and sovereign” — [about](https://patrii.cloud/about). “Free” here is a stance, not a $0 price; the pricing page charges CAD.
- Services page: “S3-compatible API” for object storage; DNS “Full API access”; floating IPs “API-driven reassignment”; custom-image “Marketplace (coming)” — [services](https://patrii.cloud/services).
- API page title is “API Documentation & Developer Reference,” but the body says “API Documentation Coming Soon” and “Our RESTful API is currently in development.” Expected items listed: “Complete REST API for all services,” “OpenAPI 3.0 specification,” client libraries, “Webhook support for events,” rate limiting. SDKs “will be available” for Python, Node.js/TypeScript, Go, Ruby, PHP, and Java. Terraform block is commented “Coming Soon: Terraform Provider for Patrii Cloud” with source `patrii/patrii` — [patrii.cloud/api](https://patrii.cloud/api).
- Documentation page repeats “Documentation Coming Soon” and lists future Getting Started, API Reference, tutorials, and FAQ. It still shows a sample `curl` — [documentation](https://patrii.cloud/documentation).
- No fetched Patrii page states a multi-cloud strategy, an infrastructure-as-code product the customer runs against other clouds, or an adapter/plugin marketplace for third-party tools. The only “marketplace” string is the future image marketplace.
- Object storage “multi-region replication” is a storage feature claim, not a multi-cloud architecture — [services](https://patrii.cloud/services).

### Inferences
- “Full API compatibility” plus OpenStack Epoxy and a Magnum Cluster API fork is consistent with them running an OpenStack cloud, but the site never tells customers to call Nova, Keystone, or Magnum. Do not document OpenStack endpoints as the supported integration surface.
- Principles are marketing claims. The documentation site that would make them operational does not exist yet.

### Gaps
- No engineering blog or architecture decision record beyond the services spec list and the March 2026 feature post.
- No OpenAPI file, version, or base-path stability statement was found. `docs.patrii.cloud` errored with HTTP 500.

## How is it hosted? Can customers self-host?

### Takeaway
Patrii Cloud is vendor-hosted SaaS. Terms place the servers in Montreal and the contract entities in Quebec. Customers are not offered a self-hosted edition of the Patrii platform. “Managed Coolify on your own instance” means a PaaS on an instance Patrii runs for you.

### Cited Findings
- Terms: technology “owned and operated by Patrii Cloud inc., running on servers located in Montreal, Quebec, Canada” — [terms](https://patrii.cloud/legal/terms).
- Privacy, 24 July 2025: “All data is stored exclusively in Canadian data centers. We do not transfer personal information outside of Canada without your explicit consent.” PIPEDA certification is described as “working towards,” not done — [privacy](https://patrii.cloud/legal/privacy). Terms section 5 repeats Canadian data centers and “working towards PIPEDA certification” — [terms](https://patrii.cloud/legal/terms).
- Home page: customers “sign up” and deploy; enterprise line says “Private cloud options available” — [patrii.cloud](https://patrii.cloud/). No install, helm chart, license, or on-prem control-plane option appears on the home, services, docs, or API pages.
- PaaS bullet: “Managed Coolify on your own instance,” “Deploy straight from Git,” “Managed security upgrades” — [services](https://patrii.cloud/services). That is a managed service on Patrii infrastructure, not a download of Patrii.
- Support is a paid add-on to the hosted service: Community (price not shown in the fetch), Standard $99/month, Premium $499/month. Email support@patrii.ca — [patrii.cloud/support](https://patrii.cloud/support).
- Contrast, different product: Patr at patr.cloud is self-hosted by design (“You run it,” “nothing phones home”) and was still closed beta on the fetched page — [patr.cloud](https://patr.cloud/).

### Inferences
- Hosting model is vendor SaaS, with an enterprise “private cloud” offer that is still Patrii-operated. Hybrid, in the sense of customer data center plus Patrii control plane, is not described. VPN Interconnect is only a Q3 2026 roadmap line.

### Gaps
- No deployment guide, region table, or status page was found. Uptime claims (99.9% SLA on VPS and the home page; terms say an SLA “defines specific uptime commitments”) were not matched to a fetched SLA document.
- Data-center street addresses and the number of Montreal sites are not published. The legal address in St-Jerome is a company correspondence address, not identified as a data center.
- ISO 27001 and SOC 2 are future program items (Q4 2026 start, completion in 2027), not current certifications — [services](https://patrii.cloud/services).

## How are external tools supposed to integrate?

### Takeaway
There is no published adapter, embed SDK, OAuth app model, partner API, or webhook catalog. The intended direction, stated as not yet shipped, is a bearer API key against `https://api.patrii.cloud`, an OpenAPI 3.0 spec, language SDKs, webhooks, and a Terraform provider `patrii/patrii`. A reseller/MSP partner URL exists, but its program terms did not render. Sample REST paths on the marketing pages contradict each other and must not be implemented.

### Cited Findings
- API page: authentication example is `Authorization: Bearer YOUR_API_KEY` against `https://api.patrii.cloud/v1/instances`. Under the heading “Available Endpoints” it lists `GET/POST /v1/instances`, `PUT/DELETE /v1/instances/:id`. The create example uses JSON fields `name`, `type` (`vps.medium`), `region` (`montreal-1`), `image`, `ssh_keys`, and a response id `inst_1234567890` with `created_at` `2025-07-21T10:00:00Z`. The same page says the API “is currently in development” and OpenAPI, SDKs, and webhooks are expectations, not shipped docs — [patrii.cloud/api](https://patrii.cloud/api).
- Services page sample is explicitly commented “Coming Soon: RESTful API” and uses different fields: `flavor` = `shared-1cpu-1gb` (not `type`), no `region`, response id `i-1234567890`, field `ip` instead of `ip_address`, same placeholder timestamp `2025-07-21T10:00:00Z` — [services](https://patrii.cloud/services).
- Documentation quick start uses `type` = `vps.small` and `region` = `montreal-1`, a third variant — [documentation](https://patrii.cloud/documentation).
- Terraform example is labeled coming soon: provider source `patrii/patrii`, version `~> 1.0`, resource `patrii_instance` with `name`, `type`, `region`. The GitHub repo of that name is empty (size 0, no commits after creation on 2025-12-14) — [api page](https://patrii.cloud/api), [GitHub API](https://api.github.com/repos/PatriiCloud/terraform).
- March 2026 blog says certificate material stored in the Secret Vault can be retrieved “through the API” and that secrets are “accessible through the console and the API.” It does not publish paths, auth, or schemas. It also lists “Terraform support” and “the Patrii CLI” under “what is coming next,” which matches the API page’s coming-soon status — [blog](https://patrii.cloud/blog/real-features-real-screenshots-acme-certificates-with-secret-as-a-service-25).
- S3-compatible object storage and “Full API access” for DNS are product claims without a published endpoint, signing scheme, or key-issuing flow — [services](https://patrii.cloud/services).
- SSO is a Q3 2026 roadmap item; “Identity as a Service” is Q1 2027. No OAuth client registration, redirect URI, or scope list was found — [services](https://patrii.cloud/services).
- Webhooks are named once, as a future API feature, with no event list or signing scheme — [api page](https://patrii.cloud/api).
- Premium support ($499/month) includes the line “Custom integrations support.” That is a support entitlement, not an SDK — [support](https://patrii.cloud/support).
- A page titled “Canadian Cloud Partner Program - Resellers & MSPs” is indexed at [patrii.cloud/partners](https://patrii.cloud/partners). Fetch on 26 October 2026 returned only the beta banner and the word “Patrii.” Reseller tiers, margins, technical onboarding, and API credentials for partners were not in the fetched body.
- Community page points at Discord, a GitHub link labeled “Coming soon,” a forum with no body text, and Reddit. No embed widget or partner technical docs — [community](https://patrii.cloud/community).
- Third-party page “Load Patrii Cloud data in Python using dltHub,” last updated 19 May 2026 (before the 18 June 2026 beta), repeats `https://api.patrii.cloud/v1/` and invents a pipeline over resources `servers` and `instances`. It is not Patrii documentation and it predates the public beta — [dlthub.com/context/source/patrii-cloud](https://dlthub.com/context/source/patrii-cloud). Do not treat it as an official client.
- Terms section 2 does say the service includes “API access and integration services,” so API access is part of the contractual description even though the reference is unpublished — [terms](https://patrii.cloud/legal/terms).
- No Clutter, Alberta 2514640, or adapter-layer mention appears on any Patrii page fetched.

### Inferences
- A third party cannot responsibly code a Patrii adapter from public docs today. The only stable facts are: bearer API key is the auth style they show, the host they show is `api.patrii.cloud`, and every concrete path is inside a coming-soon example that disagrees with the other examples. Placeholder timestamps in 2025 on pages whose beta banner is June 2026 are a further sign the JSON is sample copy.
- The practical near-term integration surfaces that are claimed as real product behavior, rather than as a future REST design, are SSH to VPS instances, S3-compatible object storage, and DNS “full API access.” None of those has a published auth recipe.
- OpenStack APIs might work if Patrii exposes them, because the control plane is OpenStack Epoxy, but that is not stated as a customer contract. The public Magnum repo is a fork of VEXXHOST’s driver, which shows interest in Cluster API on OpenStack, not a Patrii endpoint.

### Gaps
- Whether `api.patrii.cloud` responds at all was not probed (no live credential, and the docs say the API is in development). No OpenAPI URL, console URL, or API-key creation screen was found.
- OAuth, webhook signing, embed/iframe, SCIM, and a partner technical program are undocumented. The partners page did not render its body.
- No statement of rate limits beyond the API page promising “comprehensive rate limiting” later.
- CLI mentioned as future in the March 2026 post was not found as a published binary or repo.
